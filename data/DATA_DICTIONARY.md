# Data Dictionary (Phase 03)

This document records the structure and meaning of the two core datasets produced up to Phase 03, so field definitions are not lost over time.

## Dataset: [data/aml_synthetic_data.csv](aml_synthetic_data.csv)

**What it is**
- Transaction-level synthetic log for online gaming AML research.
- Each row is a single transaction event (bet, deposit, withdrawal, or transfer).
- Generated by [notebooks/01_data_generation.ipynb](../notebooks/01_data_generation.ipynb).

**Notes**
- Currency-aware fields are provided in IBM-style pairs: `amount_paid` with `paying_currency`, and `amount_received` with `receiving_currency`.
- Legacy fields like `amount` and `currency` are retained for convenience and match the payer side.
- Special routing accounts like SOURCE, PLATFORM, and SINK are used for synthetic flows.

**Fields**

| Field | Description |
| --- | --- |
| `transaction_id` | Unique transaction identifier (sequential TX_ format). |
| `player_id` | Player identifier for the session owner. |
| `from_account` | Sender account for the transaction. |
| `to_account` | Receiver account for the transaction. |
| `from_bank` | Sending institution identifier. |
| `to_bank` | Receiving institution identifier. |
| `timestamp` | Event timestamp (UTC-like). |
| `amount_paid` | Amount paid by sender in `paying_currency`. |
| `paying_currency` | Currency of `amount_paid`. |
| `amount_received` | Amount received by recipient in `receiving_currency` after FX conversion. |
| `receiving_currency` | Currency of `amount_received`. |
| `payment_format` | Payment rail or format (ACH, Wire, Credit Card, Cash, Cheque, Reinvestment, Swish). |
| `session_id` | Gaming session identifier (nullable for some actions). |
| `amount` | Legacy amount field, aligned with `amount_paid`. |
| `currency` | Legacy currency field, aligned with `paying_currency`. |
| `channel` | Channel or rail label (legacy field; often matches `payment_format`). |
| `action_type` | Transaction type: bet, deposit, withdrawal, transfer. |
| `bet_amount` | Bet size for bet actions; null otherwise. |
| `balance_before` | Account balance before the action (player perspective). |
| `balance_after` | Account balance after the action (player perspective). |
| `deposit_amount` | Deposit size for deposit actions; null otherwise. |
| `withdraw_amount` | Withdrawal size for withdrawal actions; null otherwise. |
| `game_result` | Win or loss outcome for bet actions; null otherwise. |
| `device` | Simulated device fingerprint. |
| `ip_address` | Simulated IP address. |
| `location` | Simulated geographic location label. |
| `time_since_last_action` | Gap in seconds from prior action in the session; null if not applicable. |
| `bet_direction` | Player or house indicator for bet direction; null otherwise. |
| `topology_type` | Topology label for synthetic network structures; null for normal activity. |
| `money_launderer` | Ground-truth AML flag at the transaction level (0 or 1). |
| `player_label` | Player category label (normal or suspicious pattern class). |
| `is_suspicious` | Convenience boolean for suspicious player classes. |

## Dataset: [data/aml_behavior_features.csv](aml_behavior_features.csv)

**What it is**
- Account-level behavioral feature table used for modeling.
- Each row represents a single account_id with aggregated features.
- Built in [notebooks/03_behavior_feature_engineering.ipynb](../notebooks/03_behavior_feature_engineering.ipynb).

**Notes**
- Amount-based features use normalized USD amounts when currency is available; raw amounts are used if currency is missing.
- Directional features are built from incoming and outgoing account events.
- The label is aggregated at the account level as a max over transaction flags.

**Fields**

| Field | Description |
| --- | --- |
| `account_id` | Account identifier (player or topology account). |
| `tx_count` | Total number of account events. |
| `active_days` | Number of distinct active days. |
| `mean_gap_min` | Mean inter-transaction gap in minutes. |
| `std_gap_min` | Standard deviation of gaps in minutes. |
| `night_tx_ratio` | Share of transactions during night hours (before 6 or after 22). |
| `weekend_tx_ratio` | Share of transactions on weekends. |
| `burstiness_cv` | Gap variability: `std_gap_min / mean_gap_min`. |
| `amt_mean` | Mean absolute transaction amount (USD normalized). |
| `amt_median` | Median absolute transaction amount (USD normalized). |
| `amt_std` | Standard deviation of absolute amount (USD normalized). |
| `amt_max` | Max absolute amount (USD normalized). |
| `amt_p95` | 95th percentile of absolute amount (USD normalized). |
| `amt_p05` | 5th percentile of absolute amount (USD normalized). |
| `amt_cv` | Amount coefficient of variation: `amt_std / amt_mean`. |
| `amt_p95_p05_spread` | Percentile spread: `amt_p95 - amt_p05`. |
| `amt_max_to_median` | `amt_max / amt_median`. |
| `session_count` | Number of distinct sessions. |
| `avg_session_duration_min` | Average session duration in minutes. |
| `median_tx_per_session` | Median transactions per session. |
| `max_tx_per_session` | Max transactions in any session. |
| `avg_counterparties_per_session` | Mean unique counterparties per session. |
| `in_amount_total` | Total incoming amount (USD normalized). |
| `in_tx_count` | Incoming transaction count. |
| `in_unique_counterparties` | Distinct incoming counterparties. |
| `out_amount_total` | Total outgoing amount (USD normalized). |
| `out_tx_count` | Outgoing transaction count. |
| `out_unique_counterparties` | Distinct outgoing counterparties. |
| `net_flow` | `in_amount_total - out_amount_total`. |
| `out_in_ratio` | `out_amount_total / in_amount_total` (with zero guard). |
| `tx_out_ratio` | Outgoing share of all transactions. |
| `transfer_action_share` | Share of events with `action_type == transfer`. |
| `account_money_launderer` | Account-level AML label (max over events). |
